# libpare: Pare as a C shared library

## Context

`docs/ecosystem-comparison.md` ("Outside .NET") names the first gap for use outside .NET:
the stripper is only callable from .NET. A NativeAOT shared library with a C ABI lets Rust, Go
(cgo), Python (ctypes), Ruby, PHP, and Node or Deno FFI call it in-process with no .NET runtime.
The user approved building it (2026-10-17). Tier: Standard (multi-file, API design). Plan
reviewed by Fable (verdict: sound with changes); all 10 required changes are folded in below.

## Approach

New project `src/Extrode.Pare.Native/` (NativeAOT, `NativeLib=Shared`), plus a hand-written
`include/pare.h`. Not a NuGet package (`IsPackable=false`); ships as per-RID archives from the
existing pack scripts. Core library unchanged and package-free. `AllowUnsafeBlocks` only here.

### File names and linking

- NativeAOT names the output `$(TargetName)` + ext with no `lib` prefix
  (`Microsoft.NETCore.Native.targets:74,84`). Set `TargetName=libpare` off Windows, `pare` on
  Windows: `libpare.dylib`, `libpare.so`, `pare.dll`.
- macOS install_name is `@rpath/libpare.dylib` already; Linux gets no SONAME, so add
  `<LinkerArg Include="-Wl,-soname,libpare.so" />` for linux RIDs.
- Consumers link with `-L<dir> -lpare -Wl,-rpath,<dir>`; README gives the line per OS.
- Windows import library `pare.lib` is not published (`Publish.targets:90-91` copies only the
  binary); `pack-cli.ps1` copies it from `obj/Release/net10.0/<rid>/native/`.

### C API (`src/Extrode.Pare.Native/include/pare.h`)

```c
#define PARE_ABI_VERSION 1u

#define PARE_OK 0          /* stripped; result->output holds JavaScript */
#define PARE_REJECTED 1    /* syntax error or non-erasable syntax; result->diagnostics */
#define PARE_INVALID 2     /* NULL result, NULL source with length > 0, unknown option bits,
                              invalid UTF-8, or length > 2^31 - 1 bytes; nothing allocated */
#define PARE_INTERNAL 3    /* bug in Pare; nothing allocated */

#define PARE_REWRITE_RELATIVE_IMPORT_EXTENSIONS 1u

typedef struct pare_diagnostic {   /* 5 x int32, 20 bytes, no padding */
    int32_t code;     /* 1 = syntax error, 100-107 as in docs/error-codes.md */
    int32_t line;     /* 1-based */
    int32_t column;   /* 1-based, UTF-16 code units: what browsers and the pare CLI report */
    int32_t start;    /* byte offset into the UTF-8 source */
    int32_t length;   /* bytes */
} pare_diagnostic;

typedef struct pare_result {
    char *output;                  /* UTF-8, NUL-terminated; NULL unless PARE_OK */
    size_t output_length;          /* bytes without the NUL; <= length; may hold NULs the source had */
    pare_diagnostic *diagnostics;  /* source order; NULL when none */
    size_t diagnostic_count;
} pare_result;

int32_t pare_strip(const char *source, size_t length, uint32_t options, pare_result *result);
void pare_free(pare_result *result);    /* frees and zeroes all four fields; NULL/zeroed: no-op */
const char *pare_message(int32_t code); /* static; "unknown diagnostic" outside 0..65535 or unknown */
const char *pare_hint(int32_t code);    /* static; "" for unknown */
const char *pare_version(void);         /* static, e.g. "0.4.0" */
uint32_t pare_abi_version(void);        /* PARE_ABI_VERSION the library was built with */
```

Decisions:
- UTF-8 in and out. A leading UTF-8 BOM is dropped before stripping, as the CLI's
  `File.ReadAllText` does, so columns and output match the CLI (output never has a BOM;
  diagnostic `start` still counts from the caller's first byte). Invalid UTF-8 ->
  `PARE_INVALID`, decoded with `Utf8.ToUtf16(..., replaceInvalidSequences: false)` (no throw).
- `source == NULL && length == 0` is the empty source (C idiom).
- Lines and UTF-16 columns are preserved; bytes are not when a blanked type has non-ASCII (one
  space per UTF-16 unit), so `output_length <= length`. Output buffer: one
  `NativeMemory.Alloc(length + 1)`, `Utf8.FromUtf16` straight into it.
- Diagnostics mapped in one forward pass (they arrive in source order): a cursor over the
  decoded chars yields byte offset, line and column in O(n) total, not O(n x d). Line rules
  shared with `SourceLocation.FromOffset` (LF, CR, CRLF, LS, PS).
- Thread-safe: `Parser`/`Lexer` are ref structs, statics immutable, pools are
  `ArrayPool.Shared` (verified). No exception crosses the boundary (catch-all ->
  `PARE_INTERNAL`). Message/hint/version strings: NUL-terminated buffers built in a static
  constructor from `DiagnosticMessages` (runtime-serialised, no race), never freed.
- Header notes: the library cannot be unloaded (NativeAOT); several NativeAOT libraries in one
  process are fine; linux-musl-arm64 main-thread stack-guard caveat from `work/todo.md`.

### Code layout

- `src/Extrode.Pare.Native/NativeStrip.cs`: managed core,
  `internal static int Strip(ReadOnlySpan<byte> utf8, uint options, Span<byte> output, out int
  outputLength, List<NativeDiagnostic> diagnostics)` style: validation, BOM drop, decode,
  `TypeStripper.Strip` (`src/Extrode.Pare/TypeStripper.cs`), encode, single-pass mapping.
  Unit-testable under the JIT.
- `src/Extrode.Pare.Native/Exports.cs`: `[UnmanagedCallersOnly(EntryPoint = "pare_strip")]`
  etc.: pointer and size checks, `NativeMemory` allocation, try/catch, `nuint` for `size_t`.
- Reuses `TypeStripper.Strip`, `DiagnosticMessages.Message/Hint`; CLI's
  `OptimizationPreference=Speed`. Added to `Pare.slnx`.

## Tests

- Unit (`tests/Extrode.Pare.Tests/NativeStripTests.cs`, ProjectReference + InternalsVisibleTo):
  ok output; rejection with code/line/column/byte offsets after a non-ASCII prefix, CRLF, LS;
  several diagnostics (offsets from the single pass equal a per-diagnostic recomputation);
  BOM dropped with `start` still counting it; invalid UTF-8, unknown option bit,
  length > int.MaxValue -> 2; empty and NULL+0; rewrite option; non-ASCII in a type gives
  `output_length < length`; message/hint for 65537 and -1 -> unknown.
- Integration (`tests/Extrode.Pare.Integration/NativeLibraryTests.cs`): `dotnet publish
  src/Extrode.Pare.Native -r <host rid>` once, then
  1. `cc` builds `tests/Extrode.Pare.Integration/native/smoke.c` against `pare.h`, linked with
     `-Wl,-rpath,<publish dir>` (no `DYLD_LIBRARY_PATH`), and runs it: exact output bytes; a
     rejection's fields and message; after `pare_free` all four fields are zero;
     `pare_abi_version() == PARE_ABI_VERSION`; 200,000-deep nesting -> `PARE_REJECTED` on the
     main thread and on a pthread with a 512 KB stack; 4 pthreads x 1000 calls with identical
     results. Skips when no `cc`.
  2. P/Invoke through `NativeLibrary.Load` from the test: the same checks except pthreads;
     runs on Windows (wp1).
- Break checks: commit green, then break each of byte-offset mapping, BOM drop, option
  validation, `pare_free` zeroing, UTF-8 strictness; confirm a test fails; `git checkout --`.
- Core untouched, so no corpus snapshot; full unit suite + the integration class.

## Packaging and docs

- `scripts/pack-cli.sh`: also publish `src/Extrode.Pare.Native` per RID (macOS natively, Linux
  in the existing Docker build step) into `libpare-<v>-<rid>.tar.gz` (lib, `pare.h`, LICENSE,
  NOTICE). The Linux verify container gets the build containers' clang install line and compiles
  and runs `smoke.c` against each archive. Header notes the run takes about twice as long.
- `scripts/pack-cli.ps1`: `libpare-<v>-<rid>.zip` (`pare.dll`, `pare.lib` from obj, `pare.h`,
  LICENSE, NOTICE) for win-x64 and win-arm64; checked on wp1 through the P/Invoke test.
- README `## C library` (API, a C example matching `smoke.c`'s first case, link line per OS),
  CHANGELOG Unreleased, `docs/ecosystem-comparison.md` gap row marked done, `work/progress.md`
  entry, AGENTS.md layout line for the new project.
