`work/todo.md` item "Pare: ship `build/` as `buildTransitive/` too".

## Now

- **Pare 0.7.1 is on nuget.org**: `Extrode.Pare`, `.Build`, `.AspNetCore`, `.Cli`. Husk can bump
  `PareVersion` from 0.7.0 and update the install snippets and HUSK002's message.

## Next Pare release (not in 0.7.1)

- `Extrode.Pare.Build` ships `buildTransitive/Extrode.Pare.Build.{props,targets}`, which import
  `build/`. A project that references only `Extrode.Husk.Build` gets Pare's build through the
  dependency. Tested in `BuildIntegrationTests.A_project_that_gets_the_package_through_another_strips`
  (transitive only, and transitive plus a direct reference: one import, no MSB4011).
- What Husk has to change once it moves to that version:
  - `Extrode.Pare.Build` is a `developmentDependency`, so a plain reference from
    `Extrode.Husk.Build` defaults to `PrivateAssets="all"` and writes no nuspec dependency.
    Reference it with `PrivateAssets="contentfiles;analyzers;build"`: the dependency is written,
    and `buildTransitive` still flows (only `build` is excluded).
  - HUSK002 and the three-reference install can go; keep a direct `Extrode.Pare.Build`
    reference working, since existing apps have one.
