## What Rein writes

```xml
<!-- Rein.csproj -->
<PropertyGroup>
  <PareEmbed>true</PareEmbed>
  <PareEmbedPrefix>web/</PareEmbedPrefix>
  <EnablePareDefaultItems>false</EnablePareDefaultItems>
</PropertyGroup>
<ItemGroup>
  <PackageReference Include="Extrode.Pare.Build" Version="0.4.0" PrivateAssets="all" />
  <!-- PareServeAt="/" drops the web/ folder from the name: web/home.ts -> web/home.js -->
  <TypeScriptSource Include="web/**/*.ts" PareServeAt="/" />
</ItemGroup>
```

```csharp
// Rein.Tests (PackageReference Extrode.Pare 0.4.0)
```

## Status per need

| Need | Status |
|---|---|
| N1 hook | Done both ways. `PareEmbed=true` + `PareEmbedPrefix`; and public `@(PareOutput)` with `PareSource`, `PareRelativePath`. Outputs go under `obj/.../pare/`, never the source tree, never `Content`. Incremental, edit and delete tested. |
| N1 deviation | The resource name is the path **below the project** (`web/home.js`), not below the glob. Rein's sketch (`LogicalName="web/%(PareRelativePath)"`) would give `web/web/home.js`; use `PareServeAt="/"` as above, or prefix-free. |
| N1 caveat | `PareOutDir=$(IntermediateOutputPath)pare/` does not work in a project file: `IntermediateOutputPath` is empty there (measured: it expands to `pare/`). Use `PareEmbed`, or `$(BaseIntermediateOutputPath)pare/`. |
| N2 package | 0.4.0 cut, packed into `pare/tmp/dist-lib` (`Extrode.Pare`, `Extrode.Pare.Build`, `Extrode.Pare.AspNetCore`). Vendor the first two under `rein/packages/` with the `nuget.config` in Pare's README "Restoring without nuget.org". Not on nuget.org; tag and GitHub release are the user's step. |
| N3 API | `string? TypeStripper.Strip(string, out IReadOnlyList<Diagnostic>)` added; library API documented stable for 0.x. |
| N4 Jint | Sample `tests/Extrode.Pare.Integration/JintModuleTests.cs` (Jint 4.16.4): two-module graph, `./x.js` loads `x.ts`, rejection reported as `file:line:col: error PARE100`.
